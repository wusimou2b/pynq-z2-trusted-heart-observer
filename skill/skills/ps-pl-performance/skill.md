# PS/PL性能定位

给出有范围的收益结论：哪一段被测到、减少多少墙钟/CPU、最慢连续块怎样变化、是否仍能保留原取消与故障隔离边界。

## 先固定比较对象

明确基线和候选、输入包哈希、实际ARM/PC环境、原算法/GC/预热/IPC/保护、计时覆盖范围和其它任务是否重叠。复用保存记录，保留无效点与代号转换，不为提速删除难点。没有当前授权不重新采集或加载PL。

先读[计时分层与诊断案例](references/timing.md)。先用真实链检查数值、请求身份与重置行为，再测速度；模拟等待、RAM映射、PC回放必须与真实物理总线、ARM和live负载分开命名。

## 测量

1. 普通计时、CPU/阶段插桩、cProfile分开运行。只有真实证据需要时才增加观测；优先有界预分配缓冲、收尾后导出，避免逐拍日志/IPC改变被测路径。
2. 区分PL核内周期、请求到结果/ACK、C函数返回、Python返回、剩余PS计算、完整往返。先确认是否是C已成功之后才触发外层超时。
3. 用同一单调时钟的互不重叠区间复算总墙钟。嵌套区间不能重复相加；thread CPU、process CPU与wall不是同一种量。
4. 初始定位后做原链普通ABBA。对比成熟段、后半段、最大单点和最慢连续5/10点块；平均数变好但长尾/新鲜度变差不能宣布候选可进入实采。

已规范为`run,sequence,wall_ns`以及可选`started_ns,completed_ns,cpu_ns,source_time_s,generation,valid`的CSV可用：

`python scripts/summarize_abba.py --input normalized.csv --sample-hz 25 --output NEW-abba.json`

有明确来源时间时可加`--window 35 60`。提供同钟的开始/结束时间时，连续块包含拍间空档；只有wall时明确标为调用时间之和，不能证明完整吞吐。工具保留所有行，连续块不跨缺号/代号；它不会自动证明数值等价或给出整机验收。

## 优化候选

每次选择能被独立对照的改动。重用历史准备、减少IPC或调整GIL策略时，核对全部算法字段、来源/epoch/slot及异常取消；不能因同进程诊断更快就直接去掉子进程隔离。诊断用回放收据不等于真实事务已发生。

采样周期与事务故障期限分别管理：25Hz吞吐周期是40ms，但核内看门狗、C截止、Python返回和整拍截止可有不同边界。若确需调整政策，逐一核对RTL、驱动、软件和验证，不全局20→40。

## 报告

给出输入/版本与测量范围、数值等价证据、A1/B1/B2/A2表、成熟/尾段与连续块、余量及退出状态。`wall-CPU`只称未在该CPU计时中的等待/暂停，不能直接命名纯IPC或GIL；额外时间缺少分段证据时保持未归因。

明确建议是保留、进入下一阶段或拒绝候选。收益率只适用于本次环境和负载；没有真实联合测试就不声称live改善或长期有界。
