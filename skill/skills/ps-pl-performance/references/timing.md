# 计时分层与诊断案例

## 分层

| 范围 | 典型证据 | 不能替代 |
|---|---|---|
| 核内计算 | RTL周期计数、实际时钟 | 主机端总事务时间 |
| 总线/ACK | 同一事务身份下的命令、结果、ACK与C阶段 | Python总调用或旧phase寄存器 |
| C调用 | 进入/返回时间、返回码 | C调用前后GIL交接等待 |
| Python返回 | C成功后的外层时间检查 | 核内超时 |
| 子进程处理 | CPU与wall、真实请求/回执 | 把包含等待的wall当CPU |
| IPC往返 | 正确分段的请求和回复 | 外层残差或同进程对照的全部差额 |
| 整拍/发布 | 来源到处理完成/展示年龄、连续块 | 仅算法均值 |

CPU时间可能因多线程超过wall；不能用负的wall-CPU推断“没有等待”。`cProfile`含插桩开销，热点排序有用，不能直接拿总时长当普通实时性能。

## 吞吐与保护

给采样频率f，N点名义吞吐预算为N/f秒。每点均值低于预算只说明该样本集合的平均量；还要看连续块、源到结果年龄、队列和最终发布。

例如本项目25Hz意味着40ms/点，连续5/10点名义预算为200/400ms；50Hz则是20ms/点、100/200ms。视频5fps有自己的200ms节拍。内层事务看门狗与整拍/新鲜度/退出等待不是同一个预算；具体常量以当前bit和包为准。

不要把最慢块仅剩几毫秒余量称为实时通过；搬运、刷新点、复位点和实际并发负载可能仍未计入。

## 普通ABBA的有效性

至少核对相同输入来源、有效/无效/代号记录、预热、算法字段和异常策略。A1/B1/B2/A2各自报告，不只聚合均值。外部并发必须根据该次运行窗口确认；回读时有忙内核不足以证明重叠。

`summarize_abba.py`只处理已规范的普通计时CSV：

- `run`必须为A1/B1/B2/A2；保持输入行序，不排序来掩盖重复/倒退。
- `sequence`是本次被测记录的整数来源序号；`generation`缺省为0。代号变化或缺号中断连续块。
- `wall_ns`为选定同一范围的非负有限墙钟；`cpu_ns`可缺，缺失不填0。
- `started_ns,completed_ns`可选，但每组须全有或全无、同一时钟、区间与wall一致且不重叠。有它们时连续块使用首点开始到末点完成的实际跨度，包含拍间空档；缺少时仅报告调用wall之和，不能当作完整吞吐证明。
- `source_time_s`是已声明的来源时间，未提供时不自动推断成熟/后半段；`--window`要求完整字段。
- `valid`可空/true/false；所有行均进入计时，分别报告有效性计数，不丢无效点。
- 数值等价、采集真实性、硬件时限、退出和发布由独立证据核对，工具不产生通过标志。

## 项目定位入口

在用户给定根内按需读：

- `v3b25_integration/board/README_LIVE_CPU.md`：五段墙钟、child CPU、固定缓冲、收尾后快照及观测扰动。
- `v3b25_integration/board/README_TRANSACTION_PHASE.md`：首故障时区分进入C前、C错误和`python_after_native_success`。
- `v3b25_integration/board/main_heart_transaction_profile.py`：生产C/ARM屏障在普通RAM上的成本，预期拒绝未消费ACK，不能冒充物理握手。
- `v3b25_integration/board/main_heart_transport_profile.py`：显式RAM设备与完整解码，排除物理总线成本。
- `docs/reports/2026-10-30-saved925-handoff-abba.md`：某显示候选均值无收益、最慢块变差，因此不进入live的案例。
- `docs/reports/2026-10-30-saved925-direct-vs-ipc.md`：同进程诊断较快，但隔离/取消不同，不能直接替换真实桥或把总差额全称纯IPC。

历史记录中的925点、700点预热、20/40ms等不是本skill的通用默认参数。运行旧工具前检查写死的路径、哈希和硬件导入；有缺口先制作参数化诊断副本，保留原版。
