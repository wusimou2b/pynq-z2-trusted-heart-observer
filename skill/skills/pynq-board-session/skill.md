# PYNQ交付与收尾

让用户拿到具体、可审查、可回退的板测版本，确保正在使用PL的任务不会被另一个入口破坏。

## 范围

先区分本次请求是本地打包、上传校验、无硬件短测、实际采集，还是停止/回收。沿用会话已有授权，不重复询问已授权的同一步；也不因“整理/回读/上传”而自行运行采集。

实际项目入口和状态边界见[会话与交付契约](references/session-contract.md)。本skill不保存登录凭据、固定IP或生产token，不关闭其他任务来腾资源。

## 交付

1. 选定用户指定的成功版，核对实际源包身份与当前结果。旧README中的“最新”只是历史描述。记录保留版、候选版、唯一改动与不变项。
2. 用原始静态包成员清单构建新目录；不要递归复制已运行目录里的结果、缓存和旧attempt。保留原版和失败证据。
3. 保留原保护的具体含义：启动、READY、整拍、事务、显示锁、新鲜度、退出等待分别有归属，不得统一替换常量。若需求改变政策，明确列出差异。
4. 生成入口Notebook及manifest。新入口token、结果前缀、worker的spawn绑定和child身份校验必须一起核对。测试首故障/未启动/取消/已关闭Process对象时也能导出首因。
5. 纯文件检查可用：

   `python scripts/verify_bundle.py --root PACKAGE --manifest manifest.json --output NEW-verification.json`

   按实际schema用`--file-map package_hashes`等指定成员映射；有可信manifest哈希时传`--expected-manifest-sha256 HEX`。它不替代该版本专用身份/寄存器验证。
6. 上传使用本次环境实际可用的连接方式。只补缺失或字节不符的文件，完成回读校验后交付Notebook地址和唯一运行入口。连接中断时不要顺手重跑硬件。

## 启动与停止

- 检查运行会话、原硬件租约、所有者进程、DMA和PL映射的归属。空闲内核仍可能持有MMIO/CMA；记录存在映射也不等于仍在运算。由对应所有者完成原收尾，不能仅凭idle覆盖电路。
- 用户只授权准备时，交付就绪入口后停止。用户授权直接执行时，也遵循候选自身的一次尝试、失败保存边界；不自动重复采集。
- 正式计时与冷启动/预热/排空分开。保留并发冲突事实，不把回读时内核状态当作运行时证据。
- 正常停止沿原请求渠道和收尾顺序。提交请求、撤销当前显示、采集/处理停止、写盘结束、PS退出、硬件释放、归档完成分别核实。
- 停止未完成时保留必要所有权和资源，不强杀硬件所有者、不移除故障锁、不启动另一个入口。仅处理已授权且归属明确的资源。

## 交付回执

报告新目录/包/Notebook、基线与候选哈希、校验结果、是否访问硬件、是否下载bit、实际运行入口、哪些检查已通过和待测。停止回执单独列PS自然退出、强制终止、相机/HDMI/DMA/CMA/租约及归档状态。技能创建或包身份通过均不等于板测验收。
