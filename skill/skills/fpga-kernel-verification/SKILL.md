# FPGA迁移与验证

建立从参考算法到实测结果的证据链，保留数值语义、接口和恢复/故障责任，不因硬件化而偷偷换算法。

## 开始

明确要迁移的具体计算、软件基线、实际热点与剩余PS工作，判断批量/状态复用和搬运成本。不要把“PL资源空闲”单独当作迁移动机，也不声称任意50Hz任务必然轻松。

按任务只读[验证链与接口约束](references/verification.md)的相关段落；本项目历史核、心率核和视频核仅为案例，寄存器/帧尺寸/时钟必须取当前设计。

## 数值与状态契约

写清位宽、符号、端序、舍入/归约顺序、溢出、NaN/非规格数、定点/浮点差异、复位、首帧/成熟历史、有效性及来源身份。

整数或声明逐位等价的核做精确核对；有意改变数值格式时先定义误差预算与决策边界检查，不能只看平均误差。算法门槛、选路和最终发布是否一致另行验证。

## 证据链

1. 软件参考及独立标量/可信基线：覆盖实际保存输入、边界和失败；黄金向量包含输入、期望、状态转换、生成器与契约哈希。
2. 真实RTL编译/展开/仿真：逐样本/像素及全部输出字段核对，覆盖空拍、反压、无效输入、复位/部分事务、跨代号和长历史边界。Python模拟通过不能冒充真实HDL仿真。
3. AXI/驱动契约：AW/W独立、WSTRB、B/R保持、对齐/权限、结果邮箱、ACK、epoch/token、看门狗与取消。软复位与DMA协调责任明确。
4. 独立综合/实现：资源、目标频率及约束覆盖，声明夹具/OOC范围；不能外推整板。
5. 整板集成：PS/DDR配置、地址冲突、时钟/复位、CDC、引脚、数字视频接口及真实route/timing/DRC。固定来源DCP/工具版本；失败日志不改写。
6. 从已核查的同一设计生成bit/HWH，核对device/design、地址/VLNV、参数、构建来源与manifest。配对完成仍不等于已下载。
7. 在本次授权范围内安排上板：文件/身份检查 → 已知静态或保存数据的受控硬件回放 → 短实测 → 完整联合测试。复用已通过阶段；不机械地重跑所有步骤，不自动重试失败实采。

实现可能局部并行，但每项验收只引用真实完成的证据。若用户只要求计划/审查，不启动长综合或硬件。

## 上板与交付

沿现有单所有者与保护流程，在新目录交付；保留成功版。结果区分来源记录、核回执、PS处理/发布、真实画面与资源收尾。保留失败，无效输入不删除，缺测不补零，不把模型时间冒充硬件时间。

报告完成到哪一级、具体文件/哈希、数值差异、资源/时序、未通过项及下一项最小实测。未经实际测试，不宣称板上吞吐、准确率、DDR、无限持续运行或完整系统通过。

该skill提供流程与项目定位资料；RTL/C/Python算法仍在源码中维护，不把整个旧工程复制进skill，也不固定某一次实验参数作为通用硬件要求。
