# 25Hz心率＋5fps视频：电脑浏览器绘制四曲线

本附加候选基于原成功心率代码和既有YUYV视频组合。旧文件原样保留，不运行旧入口。板端不再构造四条SVG，也不在每次状态轮询解包500点历史；正常约每半秒发送新增12/13点，浏览器保留最多500点绘图。

1. 在全新目录打开`BrowserHeartVideo60.ipynb`。确认其他板端任务实际结束、相机和HDMI OUT已接好。
2. 运行第一代码单元：冷验包后，独立子进程先运行500点合成显示数据的四组ABBA准备预算，再准备显示。预算仅比较状态轮询、整段SVG/增量构造和JSON发送准备，不是实际网络、USB或整链速度。候选每组较低且中位墙钟至少减少20%才放行；若失败保留browser-budget.json，先回读，不启动第二单元。预算完成后等待绿色“浏览器绘图已就绪，可以运行第二单元”。这个单元不加载电路。
3. 放稳手指，运行第二单元并输入`RUN-BROWSER-HEART60`。独立所有者将一次加载既有联合电路，准备最多180秒、PS700点预热最长60秒，正式共同60秒。
4. 保持页面前台。暂停、隐藏页面或数据过期会显示N/A，重新显示页面后等待新状态；它不能以旧数字冒充当前心率。首次握手过慢会在采集前拒绝，不要绕过ready检查。
5. 等待原完整收尾并保留`browser-heart-results.zip`。记录HDMI动态是否持续、心率/四曲线是否连续；失败保留，不自动重试或强杀。

没有改变25/25Hz、5fps、算法、原IIC、GC策略、队列250、100ms传输状态门、1秒BPM年龄门、2秒实际进展门或原退出责任。Canvas和时钟握手使用现有经典Jupyter comm，无新安装或服务。浏览器以握手往返包络保守估计板端时间，延迟抵达的消息会消耗其原有时效，不重新获得一秒显示许可。

所有原采样、处理和CSV仍保存；显示增量不改变算法数据流。报告的发送耗时仅为kernel发送，不是浏览器绘制、曝光到HDMI或医疗准确性测量。原心率基线保持，候选须另以真实联合60秒、时效/队列和正常收尾核验；不能只凭本地测试称修复成功。
