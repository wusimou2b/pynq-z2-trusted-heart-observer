# 联合电路：25Hz心率单独静止60秒

这是第二分支的下一步：心率在新联合电路上运行，USB相机、HDMI及视觉帧DMA均不启动。不是视频并发或完整V3B验收。原25Hz独立保底、旧视频入口和50Hz/历史核研究目录不修改。

本包完整放进新的板端目录`v3b25 joint heart25`，打开`JointHeart25.ipynb`。第一代码单元只核对文件。停止并收尾其他心率/相机/HDMI/Overlay入口，放稳手指，第二单元输入`RUN-JOINT-HEART25`，只运行一次，保持单元和页面打开。它会显式加载一次新联合bit，替换当前PL，不自动恢复旧Overlay。预热另计，正式静止60秒；失败保存，不自动重试。

Notebook保留原心率四曲线缓存显示和原保护；**HDMI屏幕没有画面是预期**。心率仍为MAX30102 ADC50/硬件平均2/有效25/处理25，6次进入确认、原PS worker、GC窗口与恢复、队列、状态100ms/结果1s/父心跳2s门不变。不使用历史核，不强制采用NLMS，也不表示准确率/抗运动收益通过。

`frozen/`中的原197文件与清单逐字节保留。新代码只在原硬件所有者的bootstrap后替换`board.prepare`，不调用旧位流加载器，不修改原算法/线程/PS进程/GC/显示或收尾实现。原Session25释放所有权时才关闭联合所有者；未确认线程已停，不额外盲关或强杀。准备阶段配置直接使用最终25Hz参数，不执行旧准备函数中暂时的50Hz配置。

原模板仍会打印“原Overlay/位流不变”或显示旧“原始50Hz”脚注。这些文字仅属于冻结参考；**本次实际联合bit/HWH及ADC50/有效25身份，以`joint_heart_result.json`和capture/summary.json中的preflight为准**。原分组件报告不回写，不能把它们的旧描述当本次硬件事实。

结束后生成包根`joint-heart-results.zip`。运行结束告诉助手读取该ZIP即可。不要删除尝试标记、绕过断言、重跑已有目录或启动两个旧loader。父进程仍按原收尾等待，不因页面似乎停止就强制关闭内核；如异常，保留页面和所有文件。

Notebook会自动保存输出/执行计数/元数据，因此新包只对其可执行代码单元做规范化哈希，而不是将合法autosave视为源码损坏；所有实际驱动、冻结源、bit/HWH仍逐文件原字节核验。
