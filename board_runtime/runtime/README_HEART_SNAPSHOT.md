# 25Hz心率单独版：快照等价减负

只运行本目录 **HeartSnapshot25.ipynb**，不要运行保留的旧JointHeart25入口。

本候选保留原209文件/197冻结心率源及原联合bit/HWH，仅将每次状态快照的三次LiveSnapshot构造合并成一次。仍使用实时的原安全检查，不缓存BPM，不降低发布频率。**不启动USB相机、HDMI或视觉送帧**；本步先恢复心率运行余量。

## 用户操作

1. 确认其他板端计算、采集及Overlay入口已结束并完成收尾，尤其不要与另一50Hz分支并行运行。
2. 在本新目录用新Notebook内核打开HeartSnapshot25.ipynb。第一代码单元只校验文件，不加载电路。
3. 放稳手指。第二代码单元人工输入 `RUN-HEART-SNAPSHOT25`，仅运行一次。它将替换当前PL，不自动恢复旧Overlay。
4. 原独立PS700点预热另计，正式静止60秒。全程放稳、不主动晃动或移开，保持单元/页面打开。原启动及退出等待不改，不把等待中误当可再次启动。
5. 保存最终输出和 `heart-snapshot-results.zip`。故障或停止未完成时保留所有记录，不重复、不强杀或启动另一入口。

原始ADC50Hz，传感器FIFO两点平均后有效原始25Hz，处理25Hz。原算法/六次进入确认、所有者GC窗口、队列与100ms状态/1秒结果/2秒父心跳/80ms时间缺口及原启动退出保护都保留。旧冻结界面的raw50或“原Overlay”文字只是参考模板；本次身份看联合电路及候选报告。

## 如何判定

“基础小试完整”只说明原基础检查、适配器安装撤回及收尾通过，**不代表心率实时恢复**。还需要核对队列等待是否持续增长、内部有效BPM是否因结果超过1秒而被隐藏，以及屏幕上的实际表现。质量/接触/无峰导致的N/A应如实保留。

`owner_heart_snapshot.json`的构造次数是经差分测试验证的实现属性，不是板端计时测量；未安装逐拍Probe，没有新计时数组。原GC、entry及joint结果全部保留，不以新汇总覆盖原错误。准确率、严格实时、DDR、完整V3B仍未验收。

静止恢复确认后，另做有时间标记的轻运动→放稳恢复；再接回已批准的5fps轻量视频并验证并发。此包不进行这些后续步骤，15fps目标也没有取消。
