# 25/25Hz＋5fps持续采集与手动停止

本目录复制已成功的332文件；新增持续运行入口，不覆盖成功版。首次板测由用户手动启动。
心率和视频均不再以60秒为正式终点。启动180秒、PS ready60秒/700点、原GC窗口、
100ms状态、1秒心率新鲜度、2秒父进展、原有界队列及满队列停止、PS原1秒退出等待不变。
不合入另一分支的新PL或历史优化，不改算法与传感器配置。

## 手动运行

只使用新`Continuous25.ipynb`，不要运行包内保留的其它历史Notebook。
确保另一分支及其它采集已收尾；连接屏幕和摄像头，不关闭其它任务来代替确认。

1. 第一代码单元：无硬件原PS短退出检查。不放手指、不加载Overlay或启动视频。未通过则回传`lean-ps-short-results.zip`，不要继续。
2. 第二代码单元：准备原浏览器绘图及正常停止按钮。等待绿色就绪提示。此单元不启动硬件。
3. 放稳手指，第三代码单元输入`RUN-CONTINUOUS25`。保持本单元和页面打开。启动和预热另计；正式开始有文字提示。
4. 首轮正式约3分钟后，点击第二单元显示区的“正常停止并导出”。不要用中断内核、停止所有内核、关页面或断电代替。
5. 等待“已停止并导出”，下载第三单元的`continuous-results.zip`回传。

## 停止状态的含义

按钮通过本会话专属的Jupyter文件接口保存停止请求，不依赖忙碌内核执行第二个回调。
请求提交即撤销页面当前心率；历史曲线仍可查看。HTTP成功仅表示请求保存，不等于硬件停止。
父进程接受后沿原收尾顺序等待视频、心率/写盘线程和PS退出，再释放DMA、缓冲、相机、HDMI及实际租约。
若底层调用未返回，显示“停止未完成，保留所有权”；不强杀硬件所有者，不重复启动。
故障或导出失败保留真实状态及原目录，不自动重试。收尾后HDMI无信号是停止输出的正常结果。

本目录只允许一次准备/启动。启动前取消会单独标记，不能算持续采集通过。
独立持续会话检查不修改旧60秒审计的false，也不代表准确率、无限时稳定、严格实时、DDR或完整V3B通过。
原GC窗口将覆盖实际正式采集至线程排空；持续运行的内存和长尾仍需本次板测观察，不承诺无限运行。
结果包含完整流式CSV、视频帧日志、显示提交日志、原GC/PS/硬件收尾报告与本次停止记录。
