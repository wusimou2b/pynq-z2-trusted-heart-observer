# 25/25Hz＋5fps 影子融合试验

此目录保留原成功持续心率源文件，只新增视频空间统计与运动旁路。融合结果只显示/记录，不能影响心率、NLMS、选路、接触/质量或新鲜度保护。不是手部检测或已验证的运动识别准确率；不能保证修复心率N/A。

## 操作

只在板子Jupyter的新目录运行ShadowFusion25.ipynb。先等另一分支和其它硬件入口确认收尾；不要同时运行、加载Overlay或关闭它们的内核。接好USB相机、HDMI、原PPG和6050；不要带电重新插线。相机固定、光照尽量稳定，手留在绿框内。若6050固定桌面而手在动，两路不一致是可能的物理事实，不应把冲突简单判成算法错误。

1. 第一代码单元只核包和原无硬件PS短退出。不放手指，不加载电路或视频；失败保留结果，不运行后面单元。
2. 第二单元准备原浏览器心率显示和“正常停止并导出”按钮，不启动硬件；返回后等绿色就绪。
3. 放稳手指，输入RUN-SHADOW-FUSION25，允许唯一所有者加载空间统计新bit，替换当前PL且不自动恢复旧Overlay。启动/700点预热另计，保持页面/单元打开。
4. 以HDMI DO倒计时为准：静止15秒→轻动15秒→强动15秒→静止15秒。DO不是预测或真值。首次四段结束后点击第二单元的正常停止按钮；原面板约3分钟提示是旧持续入口说明，不是本次要求或强制计时。

60秒后不会自动停止，HDMI提示继续静止，可在准备好时手动停止。不要用中断、关内核或断线代替正常停止。HTTP停止请求成功不等于硬件已停；只在明确停止并完成导出后启动其它入口。停止未完成则保留所有者、CMA、锁和原目录，不强杀、不自动重跑。

## 显示和规则

心率曲线仍在Notebook，HDMI显示动态视频、序号、DO及IMU/VIDEO/FUSION档位与模式，标记SHADOW ONLY。AGREED才是两路匹配一致；CONFLICT为冲突，UNMATCHED为不能时间对齐，SINGLE_IMU/SINGLE_VIDEO为单路，不算双路融合成功；缺测为UNKNOWN，不填静止0。

视频v1固定T8，使用变化像素比例0.15/0.50与最大分块均差12/75、3帧中位数和连续2次确认。两个指标不一致则UNKNOWN。首帧/缺号/配对间隔或逻辑年龄超250ms会清空确认窗口。阈值从一次既有记录提出，只是未独立验证的候选，不自动调参。

6050只复用原心率链已有运动/RMS，不增加IIC读取或逐拍IPC；原链未就绪时本路也未就绪。按真实源/处理/观察时刻因果配对，不采用未来样本。两路历史窗口不同，转变时可正常出现冲突。所有原心率保护及PS/GC/退出策略保持不变。

## 回传与界限

请回传shadow-fusion-results.zip，并说明HDMI是否全程更新、是否按提示、6050是否随同一只手移动。原continuous-results.zip和全部源日志保留；早期失败可能只有报告/身份，不读取活跃视频日志。没有保存相机图片/视频，只保存标量；前两帧像素/新统计在安全收尾后参考，不代表全程逐像素验证。

本次只评估运行/收尾、源与时间配对覆盖、旁路冲突及恢复。原心率在轻动下仍可能N/A；本轮没有授权融合控制心率，也不意味着准确率、DDR、严格实时或完整V3B通过。
