# 启动上限300秒：最小候选

使用 VideoProcess25.ipynb，四个代码单元依次手动运行，不运行全部。第一单元无硬件PS短退出；第二单元独立视频20秒，不放手指、不采集传感器；观察动态画面和序号、核对收尾。第三单元只准备浏览器显示，返回且绿色就绪后，第四单元启动一次正式60秒联合。

## 唯一政策变化

启动准备等待由180秒调至300秒。父Notebook的原drive_owner函数仅复制并替换已核对的180常量和对应错误文字，复用原字节码、全局环境、真实时钟、取消/故障/收尾流程；退出上下文后恢复原函数。原文件字节不变。视频所有者/子进程的准备期限也取同一300秒常量，准备后的正式窗口不使用启动期限。

计时起点保持原定义：父从start()返回后计时，视频从原install/preview创建时计时；父停止请求也会传播到视频。300秒是请求停止的准备上限，并非强杀或所有导出完成的墙钟上限。进行中的原生调用仍等待返回，原统一DMA/CMA收尾不变。

25/25Hz、5fps、700点、正式60秒、PS READY60秒、PS退出1秒、显示锁50ms、新鲜度1秒、A3-R/C-E80ms、队列8/250/250、算法、原GC、PL/bit/HWH均不变。未优化约82秒前置开销和约25秒重复Overlay构造；本次先检验启动余量是否足够。

原491个成员及嵌套manifest/报告保持原样，其中180秒表示保留版政策。新manifest的policy.startup_seconds、外层attempt/final的startup_budget给出本次有效300秒；parent_loop_calls记录实际调用次数，不能把旧报告字段当成本次有效期限。

## 所有权与收尾

独立硬件所有者唯一下载电路并持全局租约；视频子进程绑定已有电路，持相机、HDMI和CMA。提前导入原驱动的现有方案保持，不宣称无硬件检查，也不承诺与PS预热真正重叠；实际Overlay/端口/相机/HDMI仍在父身份与再次验包之后构造。

请求停止→视频原生调用返回及相机释放→原心率线程/PS停止→父统一停三路DMA及心率核→子关闭HDMI/释放CMA→视频实际退出→父释放全局租约。typed UserStop只在已有停止请求时计正常取消，原始异常仍保留。收尾未完成不启动其他入口、不强杀、不重试。

本地验证与保存1505点数值证据不等于ARM实时吞吐、正式60秒心率可用性、显示或DDR验收。新目录保留旧版；由用户手动运行。本地及上传过程未启动硬件。

Notebook的manifest SHA位于metadata.video_process_manifest_sha256。源单元与kernelspec冻结，执行输出不参与源身份；同一次JSON快照校验源和metadata，不使用旧校验缓存。
