# V3-A第四交付：实时50 Hz静止基准

本轮新增单窗口历史检查计算复用。ARM只读剖析已确认原检查平均约323ms，主要消耗在相关系数及重复谱功率；新live只复用同一个检查窗口内的相同计算，窗口结束释放，不跨窗口保留状态。原200点历史、每10点检查、逐延迟均值/范数/内积顺序、选择规则与所有保护不变。冻结V2及原NumPy兼容模块保留。PC精确对照不替代ARM检查，也不承诺单次优化即可通过真实配对门。

本次追加旧NumPy 1.21谱积分API兼容：只有新live的私有依赖绑定在缺少trapezoid名字时调用该版本原生trapz；冻结函数代码、频谱分段、公式、阈值及全部状态不变，不升级依赖、不修改全局NumPy或旧V2模块。新名字存在却调用失败时仍报原错误，不自动换接口掩盖故障。上一新版CLI在约5秒序号251首次收益历史检查触发缺失名字，同拍PL已完整返回；后续故障锁定不能解释为已证明的FPGA读回超时。旧结果及包保留，当前修正版须重新实际采集，不沿用上一故障会话充作通过。

公开黄金板回放已经完成；实时采集、DDR遗留负skew、自动beta效果和V3-A完整验收尚未完成。PC测试不等于板端验收，也不证明抗运动改善。原FIFO只是采集回环；NLMS核心是邮箱硬件候选，联合mix输出不能叫纯NLMS。接触异常、峰值不足或当前显示过期时，BPM=N/A是正确行为。

## 4. 四份证据分别说明什么

- raw.csv：MAX每一条已读PPG、唯一最新配对加速度、名义回投／观察重建时间、序号、FIFO指针／批量／溢出及读完成／循环时间。旧CSV字段前缀不变。原始write+flush确认后才交给处理；flush不是断电保护fsync。
- results.csv：全部冻结PS字段、真实PL公开sequence／epoch／beta／status／cycles，以及队列、PL调用、PS处理、读取到结果的实测墙钟。禁止BPM行必须为空。
- events.jsonl：每批原始flush、队列等待及首个故障等事件。故障后的未保存／未处理数量与summary一致；未知消费明确标记。
- summary.json：真实记录率、批次观察间隔分布、超20ms循环比例、队列高水位、最终PL快照、显示测量、关闭／差集、包及限值身份。启动丢弃／溢出与正式阶段分开。PL核心周期不是整条Python链延迟。

读间隔是相邻批次读取完成时间差，不是ADC采样时钟抖动。显示延迟是同拍读取到实际refresh完成时间，不能测得ADC→屏幕端到端时间。分位数统一线性插值；NumPy 1.21使用interpolation="linear"，新版使用method="linear"，按实际接口选择，不需升级板端依赖。没有测量就为空，不填写0。持续60秒只定义时长，不把3000条当作已经证明的严格样本上限。

本修正版只在新实时子类中复用固定带通系数并以同序双精度DF-II转置递推执行单点SOS，去掉每拍通用数组接口的布局检查；仍由原butter负责固定系数，不改变带通参数。不可信样本仍先更新滤波状态；重置仍清空滤波状态、阈值、峰位置、全部峰间隔、质量及选路历史。原只读算法、采集配对政策、队列容量、beta、bit／HWH、20ms期限和验收门均不改变。PC回放等价不能证明板端处理已低于20ms，也不能宣布配对率或显示门通过；必须重新提交实际四文件。
